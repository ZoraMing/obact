# Obact 自动化实战痛点记录与参考备忘

本文档用于记录在实际业务场景开发中遇到的真实痛点、以及关于文本增量解析与视觉辅助定位边界的探讨，仅作为后续遇到类似问题时的参考备忘，不作为既定的开发或排期计划。

## 文本增量解析与视觉图片描述的边界思考

核心技术路线依然以持续增量页面解析为主，用来替代长流程中昂贵且脆弱的频繁全屏截图；但在实际复杂的业务网页中，绝不能教条化地完全排斥图片，必须在文本解析与视觉辅助之间设立清晰的边界。

### 纯 DOM 增量解析的盲区与痛点

1. 巨型 DOM 与节点数量过大导致信息截断
在复杂的现代后台系统、低代码平台、BI 报表页面中，页面 DOM 节点数动辄数千甚至上万。纯文本解析即使做了提炼，依然容易超出字符预算导致内容被截断，使大模型根本看不到被截断在后面的组件。

2. 纯图标与无语义组件难以定位
大量现代前端组件只有视觉表现而无文字属性。例如纯 SVG 或背景图渲染的设置齿轮、搜索放大镜、删除垃圾桶、密码显隐小眼睛。在 DOM 树中往往表现为完全空的按钮或只有一串动态编译的混淆类名，没有任何文本或 aria 标签线索，纯文本解析在这些组件面前完全处于盲区。

3. 视觉相对空间关系的表达缺失
很多操作强依赖视觉空间方位，例如“头像右上角的小红点”、“某张商品卡片内部靠右的关注图标”、“搜索框尾部的清空按钮”。在 DOM 树结构中，这些元素可能被挂载在不同的兄弟容器甚至最外层的 Portal 遮罩层中，在 DOM 树上距离极远，但视觉上紧贴在一起。纯文本选择器很难表达这种紧邻、内部偏右等直观的空间约束。

4. Canvas 与 WebGL 图表黑盒
页面主体由 Canvas 绘制时（如数据看板、地图、图形编辑器、白板），整个画布在 DOM 树中只有一个孤立的 canvas 标签，内部的图表项和操作按钮完全不存在于 DOM 中，纯文本增量解析彻底无法获取内部元素。

### 视觉辅助定位的可能探索方向

1. 划定图文结合的触发边界
默认情况下，标准表单、链接、有文字的常规交互走低成本的文本增量解析；
当满足以下特定条件时，按需引入视觉辅助：
页面被 Canvas 大面积覆盖；
目标组件缺少可读文本与语义标签（纯图标按钮）；
DOM 节点数量过大且候选元素过多导致无法唯一定位；
需要依赖空间相对方位进行查找。

2. 局部容器裁剪截图替代全屏大图
当必须使用视觉辅助时，避免无脑截取全屏大图造成巨大的 Token 浪费和全局缩放漂移。
可采用局部视口截取或候选容器裁剪（例如只对特定工具栏、特定卡片进行局部截图），配合端侧在局部图上打上带编号的标记框（Set-of-Mark），既将视觉信息准确提供给大模型，又将图像体积和消耗降到最低。

3. 视觉空间相对辅助定位
利用端侧计算各可见元素的屏幕坐标和包围盒（Bounding Box），当大模型给出在某图标右侧、某区域下方的相对方位描述时，端侧通过空间几何关系换算出对应的候选元素或点击坐标。

## 业务实战中的其他核心痛点记录

### 1. 现代前端的半就绪幽灵状态
现代单页应用把数据和外壳解耦。例如在携程页面中，航班卡片框架和价格瞬间渲染，而机型与航班号文字却由另一个接口延后两秒异步塞入 DOM。
自动化若误以为页面已就绪便提取文本，会拿到没有航班号的半成品。提取代码中的过滤规则会把缺少航班号的卡片判定为无效项丢弃，导致真实便宜的航班被漏采，排出来的票价整体偏高。

### 2. 手写 steps.jsonl 的试错成本
手写单行 JSON 没有任何补全和校验，稍微少个标点就会解析报错。
缺少现场排查能力，流程执行到中途报错，浏览器随即退出。修改一个选择器就必须把前面的步骤重新跑一遍，排查效率很低。

### 3. 大体积接口响应被底层缓存逐出
部分业务的数据全在核心接口中，但响应体往往超过 1MB。底层的 CDP 会提示请求内容被缓存逐出（evicted from inspector cache），导致隐式网络截获失效，最终只能被迫回退到解析复杂的 DOM 树。

### 4. 流程引擎缺少轻量胶水计算能力
工作流模板只支持静态查表，不支持哪怕一行表达式。导致当前时间加七天这种简单计算无法在工作流内完成，必须由人工或外部脚本算好再传给命令行；同时抽取出的数据无法在工作流内进行内存排序或截取前五，纯声明式工作流在面对需要后处理的业务时显得僵硬。

## 可能探讨的参考方向备忘

以下仅作为外部视角的可能参考思路，存在各自的局限性，不作为既定开发目标：

1. 终端交互试错
遇到断点或错误时保持浏览器现场开着，允许在终端即时测试选择器或动作，验证通过后再落盘。

2. 端侧字段就绪保障
在提取复杂异步页面前，通过端侧守卫或属性回退机制确保关键字段已填充完毕，避免半就绪数据被误抛弃。

3. 网络请求显式捕获
针对超大接口响应，探索由端侧进程直接接管流式落盘的方式，避开浏览器内存缓存上限。

4. 动态参数的前后置轻量脚本配合
在工作流外部通过轻量的前置脚本生成动态参数注入，后置脚本处理数据清洗与排序，避免把引擎改得过重。

## 增量实战解决日志

- 2026-10-26：排查并修复 Windows 桌面有头模式下 Chrome 画面黑屏问题。根因为底层启动参数无差别传入了适用于容器无头环境的 --disable-gpu，已在启动配置中按 mode 正确剥离该参数，避免对系统 DirectWrite 渲染管线的破坏。
- 2026-10-26：解决携程机票列表航班号漏采与票价偏高问题。不依赖尚未异步填充完成的表层文本，直接在提取逻辑中加入基于元素属性（id 包含的 airlineName 与 comfort- 编码）的多源回退机制，确保 100% 捕获真实航班号，排序结果与真实页面完全一致。
