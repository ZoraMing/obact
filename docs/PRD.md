# Obact PRD v1.5.2（第一阶段）

Oct 14, 2026 · @zora

Obact（暂定名）是本项目的浏览器识别与操作工具。本版整合三轮评审的结论和最终确认（保留无头、保留接口截获、工作流用 git 管理），作为第一阶段的需求基线。第一阶段不接入 AI，验收以录制的工作流能稳定回放为准，尽量在公开的在线网站上、按真实需求进行；真实站点以复杂后台系统的管理与数据报告为主（示例：阿里云控制台），本地测试应用只承担公开网站做不到的测试。题型参考 OSWorld 1/2、BrowserGym、MiniWoB++ 等公开基准，不接入它们的评测环境。讨论过程见“PRD 讨论稿”标签页。

## 1\. 背景、目标与非目标

**背景**：研究方向是 AI 控制电脑和浏览器——AI 识别任务、操作页面、修正操作路径，之后快速回放。第一阶段先做与 AI 无关的工具，让以后的 AI 有可靠的“眼睛和手”。

**产品定义**：Obact 是一个本地运行、跨平台的浏览器工具。它把网页整理成可以选择的操作和用于判断的页面内容，提供给 LLM 或脚本；并按 JSONL 工作流带检查、带反馈地执行，可以中断、可以续跑。

**第一阶段目标**

1. 把常见网页（包括 JS 渲染、虚拟滚动、iframe、Shadow DOM）整理成可操作元素列表和内容摘要。
2. 按 JSONL 稳定执行，无人值守连续运行数小时，崩溃后续跑，单次提交零重复。
3. 运行过程留痕，作为以后训练和评估的研究数据。
4. 接口方便模型发挥：同时提供结构化和视觉两类观察与动作，参考 OSWorld、BrowserGym 等公开基准的控制方式，以后接入模型时不需要改工具。

**非目标（第一阶段不做）**

* AI 决策、视觉模型、OCR、Canvas 页面的深度解析
* 人机验证绕过；随机抖动
* 有头和无头之间的自动热切换（只做手动切换）
* 直接发 HTTP 请求取数；网络响应与页面文本的自动匹配
* 模糊指纹自愈；可视化流程编辑器
* 操作浏览器以外的桌面应用；接入外部基准的评测环境（只参考其题型和设计）
* 面向他人的产品化：多用户、权限、安装包

## 2\. 用户与场景

**用户**：第一阶段是开发者本人，同时也是使用者；以后是通过统一接口调用工具的 LLM。

|场景|描述|优先级|
|-|-|-|
|只读采集|定期从数据网站抓取列表、公告、报表，导出为文件|P0|
|后台批量操作|在后台系统批量审核、录入、修改状态，不涉及资金|P0|
|复杂后台管理与报告|登录复杂后台系统（示例：阿里云控制台），收集账单、告警、实例等数据并整理成报告文件|P0|
|无人值守长跑|在专用机上连续运行数小时，出问题再提示人|P0|
|测试任务集|参考公开基准编写的长程任务，用评分点验证工具能力|P0；第一阶段由录制完成，以后由模型完成|
|演示与调试|有头模式下看虚拟光标逐步操作，排查问题|P1|
|LLM 调用（预留）|以后由 LLM 观察页面、选择操作、生成工作流|接口第一阶段定好，AI 以后接入|

验收以公开在线网站为主，并按真实需求运行：真实站点选用复杂后台系统，示例为阿里云控制台——从 Google 搜索进入，登录后收集账单、告警、实例等数据并整理成报告。本地测试应用只承担写操作对账、故障注入和浸泡等公开网站做不到的测试。题型参考 OSWorld 1/2、BrowserGym、MiniWoB++ 等公开基准（见 9.3）。同时要求在同类站点上通用，抽取和定位不依赖站点专用代码。

## 3\. 核心概念

|概念|含义|
|-|-|
|observe|观察当前页面，返回可交互元素列表、页面摘要、页面签名和 Canvas 告警；可按需附截图|
|act|执行一个动作，返回结果|
|run|逐行执行 JSONL 工作流|
|编号（ref）|observe 给每个可交互元素的编号，并写进元素属性（参考 BrowserGym）；会话内递增、不复用；页面变化后失效|
|编号框截图（SoM）|在截图上给可交互元素画框，并标上与文本快照相同的编号，方便视觉模型对照|
|坐标动作|按截图坐标执行的点击、拖拽、滚动等动作，与按编号的动作并存|
|定位器|以后重新找到某个元素的描述。每个元素保存两类：属性/CSS、角色 + 名称；可加 within 容器消歧|
|页面签名|判断“当前是哪个页面”的规则：URL、标题、必须存在和必须不存在的元素|
|前置可达路径|工作流开头从起点走到业务列表初始状态的固定步骤；续跑时重放|
|主循环|按数据源逐条处理的部分；每轮结束写检查点|
|检查点|续跑用的进度文件，记录当前步骤、循环下标、变量和游标|
|单次提交步骤|不允许重复执行的步骤，带幂等键|
|状态未明|单次提交的动作已经发出，但没有确认结果|
|弹窗规则|被遮挡时自动处理的已知弹窗（如 Cookie 提示条）及处理动作|
|参数库|用户可编辑的明文配置文件，存账号密码和常用参数|
|接口截获（L1）|从内核缓存的最近网络响应里，按指定的 URL 规则读取 JSON 数据|
|真实站点任务|在真实网站上按真实需求运行的任务；第一阶段由录制的工作流运行，示例为阿里云控制台的复杂后台管理与数据报告|
|测试应用（Obact Lab）|自己用 Node 编写、在本地运行的 Web 应用，承担写操作对账、故障注入、浸泡和长程任务集；提供重置、状态查询和故障注入接口|
|任务集|一组带初始化、指令和评分点的长程测试任务，每个任务 10 步以上，题型参考公开基准|
|评分点|任务评分用的判定项，每项有权重；全部通过为完整完成，否则按权重给部分得分（参考 OSWorld 2.0）。与续跑用的“检查点”不是一回事|
|研究采集模式|每步保存截图和文本快照的开关，默认关闭|

## 4\. 功能需求

P0 为第一阶段必须交付，P1 为第一阶段应交付、可以延后。“验收”列对应第 9 节的测试编号：F 为本地夹具测试，T 为契约测试，R 为录制往返测试，BW 为基准工作流，C 为故障注入，E 为环境矩阵，TS 为任务集验收。

### 4.1 浏览器与会话

|编号|需求|优先级|验收|
|-|-|-|-|
|FR-01 启动与模式|本地启动 Chrome 或 Chromium：优先使用用户机器上已有的，找不到时提示安装推荐版本；支持版本区间与推荐版本见 8.3。默认有头，可按任务配置为无头；无显示器的 Linux 用 Xvfb 运行有头。两种模式只做手动切换（见 5.5），不做热切换。|有头 P0，无头 P1|E|
|FR-02 账号与登录态|每个账号一个独立的浏览器配置目录，登录一次后长期复用；遇到登录页时由参数库自动填写。|P0|BW-5、C-7|
|FR-03 浏览器池与并行|服务统一管理浏览器，任务进程崩溃不影响浏览器和登录态。同一账号的只读任务共用一个浏览器并行，有头时用标签组区分；同一站点、同一账号的写操作任务排队串行；不同账号使用不同浏览器。|P0；并行 P1|C-2|
|FR-04 标签页与 frame|每个标签页有工具内 ID（pageId），所有动作都带 pageId；新打开的标签页和跨域 iframe 自动登记。|P0|F、BW-7|

### 4.2 观察与定位

|编号|需求|优先级|验收|
|-|-|-|-|
|FR-05 页面观察|返回可交互元素列表（编号、角色、名称、关键状态）、页面文本摘要、页面签名和 Canvas 告警；超出字符预算（默认 40k）时截断并标注。数据来自 DOM 与布局信息（元素的角色、名称在页面内计算，可访问性树只作为可选视图提供）。参考 BrowserGym：编号写进元素属性，文本快照、可访问性树、DOM 和编号框截图里同一元素的编号一致；每个元素附可见比例、包围盒、是否可点击。|P0|F、T、BW-7、BW-14|
|FR-06 编号规则|编号在会话内递增、不复用，绑定到具体节点；节点失效后再使用该编号，要明确报错，不能操作到别的元素。|P0|F|
|FR-07 惰性定位|观察时只分配编号，不生成定位器；只在录制或把编号写进工作流时生成，并实测唯一性。每个元素保存两类定位器：属性/CSS（data-testid、非动态 id、class 等）和角色 + 名称；同名元素加所在行或容器（业务主键）消歧。动态 id、哈希类名、含数字或日期的文本不用于定位。提供“把编号转成持久定位器”的接口。|P0|F、BW-6|
|FR-08 页面签名|按 URL、标题、必须存在和必须不存在的元素判定当前页面；用于断言、登录检测和人机验证检测。|P0|BW-5、BW-8|

### 4.3 数据获取

|编号|需求|优先级|验收|
|-|-|-|-|
|FR-09 页面抽取|从渲染后的页面抽取表格、列表、键值对；分页或虚拟滚动的列表边翻页、边滚动边收集，按主键去重。|P0|BW-1、BW-10|
|FR-10 接口截获|内核为每个标签页缓存最近的 JSON 响应；抽取步骤按指定的 URL 规则和字段路径，读取最近一次动作之后到达的响应，还没到达就等待（有超时）。录制时用 `list_network_requests` 列出最近的响应供选择。不做与页面文本的自动匹配。用于虚拟滚动大表和需要原始数值的场景。|P0|F、BW-2、BW-10|
|FR-11 Canvas 检测|内容区被 Canvas 大面积覆盖时给出告警，不做解析。|P0|F|

### 4.4 执行

|编号|需求|优先级|验收|
|-|-|-|-|
|FR-12 动作集|点击（含双击）、悬停、填写、批量填表、键入、按键、拖拽、上传、对话框处理、导航、新建/切换/关闭标签页、截图、抽取、断言、等待、执行页面脚本、查看网络请求；坐标级动作见 FR-32。命名对齐 chrome-devtools-mcp。输入必须被网页当作真实用户操作。|P0|F、BW-7|
|FR-13 可操作性与落点|动作前确认元素可见、启用、位置稳定（间隔 50 毫秒两次采样，位移小于 1 像素）且未被遮挡；派发前一刻取坐标并核对落点。被遮挡时先查弹窗规则，连续 3 次不符则报错。|P0|F、BW-6|
|FR-14 等待策略|有后置检查的动作，检查一通过就继续；没有检查时只做短时稳定等待，上限 5 秒；纯输入类动作只等一帧。不等网络空闲，不用固定延时。|P0|BW-3、C-10|
|FR-15 动作返回|返回状态与原因、动作效果（是否导航、新标签页、对话框、页面是否变化）、断言结果和截图路径；页面变化差异按需返回，回放时不计算。|P0|T|

### 4.5 工作流与续跑

|编号|需求|优先级|验收|
|-|-|-|-|
|FR-16 JSONL 格式|一行一步，格式与单次动作调用一致，另带可选的前置/后置检查、重试、失败策略和幂等字段；支持条件、循环、子流程和变量；分为“前置可达路径”和“主循环”两段；可引用参数库、外部文件（CSV、JSONL、Excel、JSON）和运行变量。|P0|T、BW-1|
|FR-17 检查点与续跑|每轮循环或关键节点后原子写入检查点；崩溃后重放前置可达路径，再跳到断点所在的循环继续。|P0|C-1、C-3|
|FR-18 单次提交与状态未明|已确认成功的单次提交写入成功记录，续跑时跳过。动作已发出但结果未确认的标记为“状态未明”，绝不自动重试，记入待核实清单；默认停止流程并高优先级提示。可按工作流配置为跳过该条：先重置页面（重放前置路径或回到循环锚点）再处理下一条，连续 2 条状态未明则停止。|P0|BW-9、C-4、C-5|
|FR-19 卡住检测与熔断|任务每 10 秒上报心跳，30 秒无心跳或 5 分钟步骤无推进视为卡住：留存现场截图后恢复；若卡在单次提交步骤，按状态未明处理。1 小时内异常重启超过 3 次则熔断。|P0|C-6|

### 4.10 面向模型的控制接口

这一组需求让以后接入的模型能按自己擅长的方式控制浏览器：既可以读编号元素表、按编号操作（省 token、可固化），也可以像 OSWorld 那样看截图、按坐标操作（适合 Canvas 和自绘控件）。

|编号|需求|优先级|验收|
|-|-|-|-|
|FR-31 多种观察形式|observe 可按需返回：文本快照（编号元素表）、截图、编号框截图（框上的编号与文本快照一致）、可访问性树。截图坐标与坐标动作使用同一坐标系（视口像素，并返回缩放比例）。|P0|F、BW-12|
|FR-32 坐标级动作|与按编号的动作并存：按坐标点击、双击、移动、拖拽、滚动，以及键入和按键，同样走可信输入。写进工作流时尽量换算成该位置元素的定位器；换算不了就保留坐标，并标记为易失效步骤。|P0|BW-12、BW-13|
|FR-33 批量动作|一次提交多步动作，按顺序执行、遇到失败就停，返回每步结果和最后的观察，减少模型往返次数。|P1|T|
|FR-34 询问用户与报告|模型可以主动向用户提问（可带选项），也可以报告任务无法完成及原因；问题和报告走终端和接口推送，回答作为返回值，与人工接管共用通道。|P1|TS|
|FR-35 工作区文件|在工作区目录内列出、读取、写入文件（下载的文件、附件、笔记），不能越出工作区。|P1|F|
|FR-36 任务评测|支持“初始化 + 指令 + 带权重评分点”的任务格式（参考 OSWorld 2.0）；评分点通过测试应用的状态接口或页面断言判定，运行后给出部分得分和是否完整完成。|P0|TS|

## 5\. 关键流程与异常处理

正常运行只有一条路径；三类异常各走一条固定的处理路径，单次提交在任何情况下都不自动重试。

\[embedded content: 异常处理 · 3 条固定路径]

定位失败先查弹窗规则再转人工；单次提交未确认时只标记、不重试；崩溃后重放前置路径再回到断点。

### 5.1 正常运行

1. 服务按账号启动或复用浏览器，任务子进程连接浏览器并分配标签页。
2. 执行前置可达路径，到达业务列表的初始状态。
3. 主循环逐条处理：定位 → 可操作检查 → 执行 → 后置检查 → 下一步。
4. 每轮结束写检查点、追加采集结果、记录已确认成功的单次提交。
5. 全部完成后导出 CSV 或 Excel，写运行报告。

### 5.2 崩溃与卡住

1. 服务发现心跳超时或步骤长时间无推进，留存现场截图。
2. 如果卡在单次提交步骤，按 5.3 处理。
3. 重启任务进程，必要时重启浏览器。
4. 重放前置可达路径，回到列表初始状态。
5. 读取检查点，跳到断点所在的循环继续。

### 5.3 状态未明

* **默认**：记入待核实清单，停止流程并高优先级提示；人工核实后台真实状态后再手动续跑。
* **配置为跳过时**：记入待核实清单 → 重置页面（重放前置路径或回到循环锚点）→ 处理下一条；连续 2 条状态未明则停止，防止系统性故障时一路跳过。

### 5.4 人工接管

1. 触发后暂停任务，留存现场截图，终端和接口推送同时提示。
2. 如果任务是无头运行，先按 5.5 切到有头。
3. 用户直接在浏览器里处理。
4. 用户点“继续”，一次确认写回性质（仅本次、存为弹窗规则、固化为步骤）和要保存的参数。
5. 工具重新观察页面、校验前置检查后继续。

### 5.5 有头与无头的手动切换

1. 只在检查点边界切换，不做热切换。
2. 该任务写检查点并挂起。
3. 如果同一浏览器上还有其他任务，等它们到达检查点，或由用户确认中断。
4. 关闭当前浏览器，用另一种模式、同一个配置目录重启。
5. 各任务重放前置可达路径，从检查点继续。

切换会丢失内存中的页面状态、sessionStorage 和当前的验证挑战，这是有意接受的代价；需要频繁人工处理的站点直接用有头运行。

### 5.6 接口截获

1. 运行时，内核只缓存与工作流中接口规则匹配的 JSON 响应；录制和 LLM 探索时缓存全部 JSON 响应。每个标签页最多 30 条，单条大小有上限，超出淘汰最早的。
2. 每次动作开始时递增一个动作序号，缓存条目记录到达时的序号。
3. 抽取步骤读取“上一个动作开始之后到达、URL 匹配”的最近一条；还没到达就等待，超时报错。这样不需要提前挂监听，也不会错过点击后几十毫秒内就返回的响应。
4. 按字段路径取出数据（如 data.list），按主键去重后写入结果。

### 5.7 录制

1. 用户用命令行或统一接口开始录制，内核向页面注入录制脚本。
2. 用户正常操作；每个动作生成一行 JSONL 草稿，输入值提示存进参数库。
3. 需要接口数据时，用户用 `list_network_requests` 从最近的响应里选一条，生成抽取步骤。
4. 结束录制后立即快速回放一遍，通过才保存。

### 5.8 任务集运行

1. 调用测试应用的重置接口，恢复本次运行数据空间的初始数据。
2. 执行任务的初始化步骤：打开页面、登录、准备文件。
3. 由工作流（第一阶段）或模型（以后）通过 Obact 完成任务；模型可以组合使用文本快照、截图、编号框截图和坐标动作。
4. 读取测试应用的状态接口和页面断言，按评分点打分。
5. 保存轨迹和得分。

## 6\. 非功能需求

|类别|要求|
|-|-|
|稳定性|无人值守连续运行数小时；任务进程或浏览器崩溃后自动恢复；单次提交零重复|
|性能|快速模式下回放速度至少是手动操作的 3 倍；主要靠断言驱动的等待，而不是固定延时|
|资源|截图占用受数量上限约束；接口缓存有条数和大小上限；长时间运行内存无持续增长|
|跨平台|Windows、macOS、Linux；只涉及浏览器操作和文件存取；无显示器的 Linux 用 Xvfb 运行有头浏览器|
|精简|核心小、依赖少，不引入数据库和系统级守护进程；模块边界清楚，便于多个 agent 并行开发和单元测试|
|可观测|每步留痕可回看；运行状态随时可查；每次运行生成报告|
|安全与合规|本地运行；参数库明文是已知风险，暂不处理，但敏感参数在日志和留痕中脱敏；调试端口只绑定本机；不绕过人机验证；批量采集前确认站点条款允许|

## 8\. 系统架构与技术基线

## 9\. 验收方案

验收从确定性的本地测试逐层走到真实站点长跑。正式验收以本地夹具、模拟站点和 OSWorld 2.x 任务为准，公共练习站点只用于回归。

### 9.1 验收层级

|层级|环境|目的|何时执行|
|-|-|-|-|
|夹具测试（F）|本地 HTML 夹具、MiniWoB++|逐项验证识别、定位、等待、抽取、截获和原子操作，结果确定|每次提交|
|契约测试（T）|JSON Schema|observe、act、工作流步骤、检查点和接口消息的结构|每次提交|
|录制往返（R）|夹具、公共练习站点、测试应用|录制后立即回放必须通过|改动录制或定位逻辑时|
|基准工作流（BW）|公共练习站点、测试应用、本地夹具|端到端功能、速度和识别对照|每个里程碑|
|故障注入（C）|测试应用 + 请求拦截|续跑、幂等、恢复、熔断|每个里程碑|
|环境矩阵（E）|三个系统 × 有头/无头|跨平台与模式|里程碑 5|
|浸泡测试|测试应用（本地），专用机|8 小时稳定性与资源|里程碑 5|
|任务集验收（TS）|测试应用的长程任务集|各类挑战题型的长程任务能否完成，以及长跑与评分|里程碑 5|
|真实站点验收（RS）|阿里云控制台|真实需求下的长程运维任务|里程碑 5|

### 9.2 指标与通过标准

验收数值均已确认。

|指标|通过标准|测量方法|
|-|-|-|
|真实站点任务|录制的工作流按计划回放 5 次（可分多天），全部完成，输出与页面显示一致。容错：弹窗、加载慢、会话过期由 Obact 自动处理；登录验证可以人工处理；其他人工介入 5 次合计不超过 1 次，且写回后不再出现|运行记录；与页面人工抽查对账|
|连续运行（测试应用）|8 小时零人工介入，不含预设的登录过期和人机验证|按介入日志计数|
|任务集可达性|第一阶段 7 个长程任务经录制完成并固化后，回放时评分点全部通过|每个任务回放 3 次，3 次都完整完成|
|任务集长跑|任务集循环回放 4 小时（每轮重置数据空间），人工介入不超过每小时 1 次|介入日志；介入指需要人操作才能继续的事件|
|观察与动作覆盖|完成任务集、真实站点任务和 MiniWoB++ 的每一步，都只用 Obact 的观察和动作；记录哪些步骤只能用坐标动作|完成时记录每步所用的接口|
|组件识别|可交互元素的召回不低于 BrowserGym|BW-14：同一批页面对比两者的提取结果|
|回放速度|至少为手动操作的 3 倍|BW-4：手动操作 3 次、快速模式回放 3 次，各取中位数；研究采集模式不计入|
|续跑|随机注入 20 次崩溃，全部续跑成功|C-1、C-2|
|单次提交重复|0 次|测试应用的服务端按幂等键记录每次提交，运行后对账|
|数据完整性|条数与数据源一致，重复为 0|BW-1 对账 1000 条；BW-2、BW-10 对比接口截获与页面抽取|
|定位可靠性|动态 id、类名等场景全部通过；定位器失效时一律转人工，误点为 0|BW-6 与改版夹具|

### 9.7 录制往返与契约测试

* **录制往返（R）**：在夹具、Quotes to Scrape、Sauce Demo、The Internet 上各录制一个流程，结束后立即快速回放，必须一次通过；同时检查录制出的定位器中没有动态 id 或哈希类名。
* **契约测试（T）**：observe、act、工作流步骤、检查点、待核实清单和接口消息都用 JSON Schema 校验；Python 客户端对每个方法各调用一次。

### 9.8 验收记录

每次运行自动生成报告，包含：

* 运行时长、步骤数，成功、失败、人工接管和续跑的次数
* 状态未明清单及对账结果
* 每分钟内存采样，截图目录和接口缓存的大小
* 基准工作流的速度对比
* 人工介入日志：时间、原因、处理方式、写回性质

## 11\. 风险与对策

|风险|影响|对策|
|-|-|-|
|真实账号被误操作|以后接入模型时可能改动线上资源|使用只读权限的 RAM 子账号；写操作只演练到确认页|
|登录验证与多因素认证|登录需要人工处理|保留登录态；按真实需求的频率运行，接受少量人工介入|
|搜索引擎拦截自动化访问|进不了任务入口|转人工；备用入口直接打开控制台地址|
|控制台改版|定位失败|转人工并写回；用页面签名尽早发现改版|
|真实数据敏感|账单金额和实例 IP 进入留痕|留痕只存本地；导出研究数据前脱敏|
|自写任务偏简单|反映不出模型面对的真实难度|以真实站点任务为准；测试应用的任务按 OSWorld 2.0 的挑战类型编写，每类至少一个|
|测试应用本身有缺陷|把应用的问题误判成工具的问题|测试应用保持简单；每个模块有自己的冒烟测试|
|无头更容易被识别|无头任务更常触发验证|需要频繁人工处理的站点直接用有头|
|切换模式丢失现场|当前验证挑战和内存中的页面状态丢失|只在检查点边界切换，重放前置路径；有意接受这个代价|
|接口缓存占用内存|长跑时内存增长|运行时只缓存匹配规则的响应；条数和单条大小设上限|
|页面数字经过格式化|页面抽取损失精度|需要原始值时用接口截获|
|坐标步骤容易失效|页面布局变化后点错位置|固化时尽量换算成定位器；换算不了的标记为易失效，回放前先核对落点|
|明文参数库 + 本地调试端口|本机任何程序都能拿到登录态和密码|长跑只放专用机；调试端口只绑定本机|
|公共练习站点改版或下线|回归测试失效|开源站点本地部署；正式验收不依赖公共练习站点|
|防休眠|无法用代码跨平台处理|写进部署说明|

## 12\. 待确认事项

* 用现成模型经 Python 端口试跑任务，检查接口是否够用
