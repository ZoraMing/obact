## 2. 现状

M1 已完成（[M1_REVIEW](M1_REVIEW.md)）。M2 已有 8 个支撑模块（约 5400 行，各自单测通过）：类型与 `Executor` 接口、模板 / 参数库 / 工作区文件、工作流加载校验、运行目录存储（检查点原子写等）、页面抽取与接口缓存、采集输出、最小监督。**缺的是把它们串起来的 runner 与执行器**，所以出口用例一个都没跑过。

## 3. 设计要点（多页面部分）

多页面流程只需要 runner 里的一张**别名表**，不需要在 core 里新增任务上下文：

- `opens: "docs"`：这一步执行后，`act` 结果的 `effects.new_pages`（M1 已有）里恰好一个新标签页，就把它绑定到别名 `docs`；0 个或多个报错；别名已占用报 `invalid_params`。
- `pageId` 写别名时，runner 先解析成真实编号再交给 act；别名未绑定或页面已关闭报 `page_not_found`。
- `extract` 加可选 `into`，把结果写进变量，回原页面 `fill` 时用 `{{var:..}}`。
- 检查点不记别名：续跑时 `main` 由前置路径重建，辅助页不恢复；需要的步骤自己重新 `opens`。
- 不做导航链、页面树、页面表对账：要回溯就用已有的 `navigate_page` 的 `back / forward`。

详见 [多页面设计](DESIGN_MULTIPAGE.md)。

**估计**：约 **15~20 个 agent 小时，墙钟 1~1.5 天**（原计划的一半）。

### 执行顺序

```
W0 ─▶ W1(S1→S2→S3) ─┬─▶ W2 ─▶ W4 ─▶ W5
      W3 ───────────┘
```

- 只有两条线：A 线 W0 → W1；B 线 W3（与 W1 并行，文件不重叠）。W2 在 W1 的 S1 完成后由单个 agent 做，W4 在三者都合并后做。
- 每个切片或包结束都提交并推送，`npm run check` 通过；额度或进程中断时靠已提交的进度恢复。

## 5. 出口用例（W4：5 个 E2E 文件覆盖 9 个编号）

| 文件 | 覆盖 | 内容 | 判据 |
|---|---|---|---|
| `collect` | BW-1、C-3 | Lab 大表分页采集 50 页 1000 条，主键为详情链接，导出 CSV；第 23 页被杀后续采 | 与不崩溃结果完全相同，零重复；CSV 带 BOM |
| `scroll-api` | BW-2、BW-10 | 同一份数据分别用页面滚动与接口截获采集；BW-2 取 100 行，BW-10 取 2000 行 | 两种方式条数一致、内容一致；各 ≤ 3 分钟 |
| `orders` | BW-9、C-4、C-5 | 批量审核订单，注入提交超时；默认模式遇状态未明即停；跳过模式其余照常；连续两条超时停止 | 以 Lab 服务端幂等键计数为判据：零重复；待核实清单与服务端对得上 |
| `kill-resume` | C-1 | 订单批量中随机时刻 SIGKILL 子进程，监督进程拉起并续跑，固定种子，2 次 | 最终结果与不被杀一致 |
| `multipage` | BW-15 | 编辑表单时新标签打开文档页取值，关闭，回原页填写余下并提交；再注入一次进程被杀 | 服务端恰好一次提交且值正确 |

通用判据：每个用例结束后核对 **服务端状态**（Lab `_lab/state`）与 **引擎产物**（`data.jsonl`、`side_effects.jsonl`、`unverified.jsonl`）互相对得上，这是 M2 最有价值的断言。

## 6. 质量门

1. 每个切片或包合并前：`npm run check` 全过；涉及浏览器的再跑 `npm run test:bench`；浏览器缺失时测试必须失败（`OBACT_REQUIRE_BROWSER=1`）。
2. 测试少而有价值：runner 用假执行器测逻辑，真浏览器只在 E2E 里用。
3. 契约变更只在 W0 做。
4. 两条线用独立 git 工作树，文件所有权不重叠；小任务一个提交，提交说明写工作包。
5. 不引入新依赖。

## 7. M1 评审带给 M2 的接口约定（W0 写进 DESIGN.md）

1. **`dialog_blocking` 不再一律是“未发出”**：后置检查或等待期间被对话框打断时，`error.details.dispatched` 为 true，表示动作已执行。runner 对 `once_only` 步骤必须读它：为 true 按“已发出、结果未确认”处理（记 unverified、不重试）。
2. **接口缓存的大整数**：超过 2^53 的整数以十进制字符串保留。
3. **Lab 数据量**：`_lab/reset` 可带 `{"orders": 1000}`；故障开关有校验；`drop_rate` 对写接口是“先落库再断开”。
4. **导航协议**：`navigate_page` / `new_page` 只放行 http、https、about:blank 和工作区内的 file:。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 有头 Chrome 点击导航后丢输入 | E2E 用 chrome-headless-shell；有头未验证，文档注明 |
| runner 的组合复杂度（单次提交 × 跳过 × 续跑） | 垂直切片，表驱动单测；先保 `orders`、`kill-resume`、`multipage` 三个用例（核心承诺） |
| SIGKILL 类测试依赖时序 | 确定性钩子（第 N 步后自杀）+ 固定种子；测试里调小心跳间隔 |
| `opens` 在弹窗或广告场景下不唯一 | 报 `not_unique` 转人工，弹窗规则留给 M3 |
| 估时仍偏乐观 | 紧时先砍 `scroll-api` 的 2000 行（降为 500），再砍 `collect` 的页数 |
